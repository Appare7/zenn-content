2026年7月、87年ものあいだ誰も崩せなかった数学の予想が、SNSに投げられた216文字で終わった──そんな話が流れてきました。早すぎません？この記事では、海外の記事と数学者のブログをいくつか読み比べて、事実がそろっているところだけをまとめていきます。

## 何が起きたのか：ワールドカップの裏で、Xに1行だけ投げられた

世界がFIFAワールドカップ（サッカーの国際大会）決勝、スペイン対アルゼンチンを見ていた2026年7月の日曜の夜。数学のコミュニティでは、まったく別の方向でざわつきが起きていました。

きっかけは、Levent Alpöge（レヴェント・アルペーゲ）という数学者による、X（SNS）への投稿です。

「hello there the jacobian conjecture is false thanx」

日本語にすると、だいたいこんな感じです。

「やあ、ヤコビアン予想は偽だよ、どうも」

ゆるすぎる。87年ものの難問の決着報告がこれ。  
もう少し「重大発表です」みたいな空気を出してもよさそうなのに、まさかのこの軽さです。

Alpöge は AI（人工知能）企業 Anthropic に所属する数学者です。この投稿は2000万以上のビューを集めました。

しかも、すごいのは投稿の軽さだけではありません。反例（予想が成り立たないことを示す具体例）そのものが216文字しかなく、X投稿ひとつに丸ごと収まったんです。

今回崩れたヤコビアン予想は、1939年に Ott-Heinrich Keller（オット・ハインリヒ・ケラー）が高次元へ一般化した形で知られています。だから「87年」です。さらにルーツをたどると、2次元版は1884年にチェコの数学者 Ludwig Kraus（ルートヴィヒ・クラウス）までさかのぼります。

そして1998年には、フィールズ賞（数学のノーベル賞と呼ばれる賞）受賞者の Stephen Smale（スティーヴン・スメール）が「次の世紀の数学問題」リストにこの予想を入れています。つまり、数学の中でもちゃんと大物扱いされてきた問題なんですね。

## そもそもヤコビアン予想って、何を言ってるの？

![](/images/jp-digest-20260803-ai-math-conjecture/figure2.png)

ざっくり言うと、ヤコビアン予想は「行きの関数がキレイなら、帰り道も必ずあるはず」という予想です。

もう少しだけ数学っぽく言うと、こうです。

多項式でできた写像（入力の点を出力の点に移す変換）があるとします。そのヤコビ行列式（各変数で微分した値を並べた行列の行列式）が0でない定数になるとき、その写像は必ず逆写像（出力から入力へ戻す変換）を持ち、しかもそれも多項式で書ける、という主張です。

エンジニア向けにたとえるなら、こんな感じです。

入力を出力に変換する関数があって、「情報が潰れていない」ことを示すチェック値がずっと一定なら、デコーダも必ず作れるはずだよね、という直感です。

うん、気持ちはわかりますよね。  
でもこの直感が、87年間、誰にも証明も反証もできなかったわけです。

Alpöge と AI が見つけた反例は、3変数 `x, y, z` の写像です。実際の式はこれです。

```text
a = (1+xy)^3 z + y^2 (1+xy)(4+3xy)
b = y + 3x(1+xy)^2 z + 3xy^2 (4+3xy)
c = 2x − 3x^2 y − x^3 z
```

この写像のヤコビ行列式を計算すると、ちゃんと定数の `−2` になります。つまり、予想の前提はバッチリ満たしています。

なのに、この写像は「一般に3対1」です。つまり、3つの別々の入力点が、同じ出力点に潰れてしまいます。全単射（1つの入力が1つの出力に対応し、逆にも戻れる対応）ではありません。だから逆写像が作れません。

予想、ここでアウトです。

ただし、ここはかなり大事です。崩れたのは3次元以上の場合です。2次元、つまり平面の場合のヤコビアン予想は、いまも未解決のままです。

なので「ケラーのもとの平面の問題が反証された」と書くのは間違いです。ここ、報じ方によってはボヤけているので注意したいところです。

ついでに、`n≥3` の Dixmier予想（ディクスミエ予想）も同時に崩れることが明示的に示されました。

## AIは実際、何をやったのか

![](/images/jp-digest-20260803-ai-math-conjecture/figure3.png)

今回使われたのは Claude Fable 5（クロード・フェイブル5）という、数週間前に公開されたモデルです。

ここが誤解されやすいところです。  
「一行のプロンプト（AIへの指示文）を投げたら、いきなり答えが返ってきた」わけではありません。

Alpöge は、3次元空間から自分自身への多項式写像を構築するように、AIをかなり具体的に方向づけていました。

AIがやったのは、膨大な多項式写像の空間から、条件を満たす一例を効率よく掘り当てることです。干し草の山から針を探す作業ですね。

そして見つかったものは216文字。どの数学者でも紙と鉛筆で確かめられるサイズでした。

ここに「見つけるのは死ぬほど難しいけど、確かめるのは一瞬」という非対称性があります。これが今回の成果のキモです。

検証も、複数の角度から独立にやられました。

- ヤコビ行列式が `−2` であることの直接計算
- 有限体（要素の数が有限の世界）の上での点の数え上げ
- 実際に衝突する点の明示

つまり、「なんとなくそれっぽい式をAIが出しました」では終わっていません。ちゃんと数学としてチェックできる形に落ちていたわけです。ここ、けっこう大事です。

面白い後日談も2つあります。

1つ目。OpenAI（AI企業）の研究者 Aaron Lou（アーロン・ルー）によると、Codex（コーデックス）の社内版が本質的に同じ反例を独立に見つけていました。つまり、一発の偶然ではなさそうなんです。

2つ目。開発者の Alexis Gallagher（アレクシス・ギャラガー）は GPT-5.6（AIモデル）を使って、この1つの反例から無限個の族を生成しました。ただし、まだ誰も検証していません。ここは「おお！」で止めつつ、「まだ確定ではないよね」とブレーキも踏むところです。

## 2026年、AIと数学のあいだで起きていること

![](/images/jp-digest-20260803-ai-math-conjecture/figure4.png)

今回のヤコビアン予想は、突然ポンと出てきた変な事件ではありません。2026年の数学とAIのあいだで起きている流れの中の一点です。

時系列で見ると、かなり濃いです。

- 2025年半ば: 国際数学オリンピック（IMO、高校生などが数学の難問を競う国際大会）の6問中5問をAIが解いた。
- 2026年2月: 「First Proof」（ファースト・プルーフ）という新しい試験がスタート。11人の著名な数学者が、自分の研究の途中で出てきた補題（大きな定理へ向かう途中で証明する小さな定理）を持ち寄って問題にした。プレプリント（査読前の論文）は2月6日公開。狙いは、問題がどのAIの学習データにも存在しないようにすること。AIには1週間の解答期限が与えられた。
- 2026年5月: OpenAIのモデルが、80年前のエルデシュ予想（組合せ幾何の問題）を反証した。
- 2026年6月: 16大学の研究者が「ライデン宣言」を発表。
- 2026年7月20日: ヤコビアン予想の反例。

First Proof を報じた記事の見出しが象徴的です。

「Mathematicians issue a major challenge to AI: Show us your work」

日本語にすると、「数学者からAIへの挑戦状: 過程を見せろ」くらいです。

答えが合っているかどうかだけではなく、どうやってそこに至ったかを見せろ、という問題意識ですね。この話は、次の「数学者がなぜ落ち着かないのか」にそのままつながります。

## なぜ数学者は「落ち着かない」のか

今回の反応は、「AIすごい派」と「AIけしからん派」にきれいに割れている感じではありません。むしろ、みんな「すごい」と「困った」を同時に抱えているように見えます。

Timothy Gowers（ティモシー・ガワーズ、フィールズ賞受賞者）は称賛側です。今回の件を、「AIが、専門外の人でも名前を聞いたことがあるレベルの大問題を解いた初めての例」と評価しています。

一方で、Kevin Buzzard（ケヴィン・バザード、インペリアル・カレッジ・ロンドン）は「It is a big day」（大きな日だ）と言いつつ、こんなポイントを挙げています。

AIは「how（どうやって）」は出してくれるけど、「why（なぜ）」は出してくれない。

これ、エンジニアにもけっこう刺さりませんか。  
動くコードは出てきた。でも、なぜこの設計なのか、どこまで保つのか、壊れるとしたらどこなのか。その説明がないと、安心して乗れないことってありますよね。

Akhil Mathew（アキル・マシュー、シカゴ大学）の言葉もかなり刺さります。

「One can check out that it's correct, but it would be nice to be able to tell a story」

日本語にすると、「正しいことは確認できる。でも、物語を語れたらもっといいのに」という感じです。

数学者が欲しいのは「正解」だけではなく、「なぜそうなるかの理解」なんですよね。反例は正しさは配ってくれるけど、理解は配ってくれません。

Mathew はこの状況を「a very rapid and very unsettling change」（とても速くて、とても落ち着かない変化）と表現しています。特に若い数学者にとってしんどい、と。

ただし Buzzard は、AIに置き換えられない部分もはっきり言っています。それは「問題を立てる力」です。彼の言葉では taste（センス）。

「People have tried to get machines to ask questions, and they're abysmal」

日本語にすると、「機械に問いを立てさせようとした人はいるけど、それはひどいものだ」くらいです。

答えを探す力と、そもそも何を問うべきかを見つける力は、やっぱり別物なんですね。

## 「AIが数学を解いた」は、まだ言いすぎ

![](/images/jp-digest-20260803-ai-math-conjecture/figure5.png)

ここは少し冷静にいきましょう。今回わかったことと、まだわかっていないことを分けます。

| 区分 | 中身 |
| --- | --- |
| わかったこと | 3次元以上のヤコビアン予想は偽。式は厳密に計算でき、誰でも再現できる |
| わかったこと | 反例探しのような「探索」タスクで、LLM（大規模言語モデル）が人間の何年ぶんかの試行を肩代わりできる |
| まだ言えないこと | 反例を見つけることと、定理を証明することは全く別物 |
| まだ言えないこと | プロンプトの全文、モデルのセッションログ、研究のワークフローは公開されていない |
| まだ言えないこと | どこまで自律的で、どこから人間が操縦したのかは、はっきりしていない |
| まだ言えないこと | Anthropic からの公式発表はなく、査読も通っていない（2026年7月26日時点） |
| まだ言えないこと | 平面、つまり2変数の場合は未解決のまま |

特に大事なのは、「反例」と「証明」はまったく違うという点です。

反例は、定義に照らして厳密に計算して、生き残ればOKです。今回なら、ヤコビ行列式が `−2` になること、そして3対1になって逆写像が作れないことを確認できればいい。

でも証明のほうは、無限や代数拡大についての議論に、微妙な穴が入りうる世界です。今回の成功は、LLMが一般に信頼できる定理証明器だということまでは示していません。

Andrew Blumberg（アンドリュー・ブルームバーグ、コロンビア大学）も、「証明と反例はまったく違う」「機械がたくさんの多項式を確かめるのは、そんなに難しいことじゃない」と釘を刺しています。

ここでいちばんモヤっとするのは、計算結果は厳密で再現できるけど、発見のプロセスは追えないことです。

式そのものは紙と鉛筆で確かめられる。  
でも、AIと人間がどういうやり取りをして、どこでどれくらい人間が誘導して、どこからAIが飛んだのかは、外から監査できません。

だから「AIが数学を征服した！」と叫ぶには、まだだいぶ早いです。すごい。でも、まだ落ち着いて見る必要がある。そんな温度感です。

## エンジニアが持ち帰れること：「検証が安い問題」を探せ

ここからは、実務に引き寄せた話です。

今回の成果を一言でまとめると、「生成は死ぬほど高いが、検証はタダ同然」という形の問題に、LLMをぶつけたら勝った、という話です。

たとえるなら、合鍵づくりに似ています。  
ドアに合う鍵を削り出すのは大変です。でも「合ってるかどうか」は、ドアに挿せば1秒でわかります。

この構造の問題なら、AIに何万本削らせても、判定コストがほぼゼロだから回ります。

ソフトウェア開発って、実はこの構造だらけですよね。

- テストが通るか
- 型が通るか
- リンター（コードの書き方をチェックする道具）が黙るか
- ベンチマーク（性能を測るテスト）の数字が上がるか

全部「作るのは大変、確かめるのは一瞬」です。だからコーディングエージェント（コードを書くAIの補助役）がここまで実用になった、という見方ができます。

逆に、検証が高い場所ではまだ人間が要ります。

- この設計は妥当か
- この仕様でユーザーは幸せか
- そもそもこの問題を解くべきなのか

ここは、自動テストを回しただけでは決まりません。

Buzzard の「how は出るが why は出ない」と、まったく同じ構造なんです。AIは「こうやれば通る」を持ってくるのがどんどんうまくなっています。でも、「なぜそれをやるのか」「その問いは良い問いなのか」は、まだ人間側の仕事として残っています。

なので、実務での指針はかなりシンプルです。

AIを入れる前に、「これ、出てきた答えを安く確かめられる？」を先に考えてみてください。

検証手段がないところに生成を突っ込むと、レビューコストで元が取れなくなります。逆に、検証が自動化できているところは、どんどんAIに投げていい領域です。

「問題を立てる力」が人間側に残るというのも、数学者の話とエンジニアの話でまったく同じですよね。

## まとめ

- 87年もののヤコビアン予想が、3次元以上で崩れました。反例は216文字で、誰でも検証できます。
- ただし平面の場合は未解決で、査読も通っておらず、発見プロセスも公開されていません。「AIが数学を征服した」では、まだありません。
- AIが強いのは「探すのが大変で、確かめるのが簡単」な問題です。ここは実務にもそのまま効きます。
- 人間に残るのは、「なぜ」を語ることと、問いを立てること。
- なので次にAIへ仕事を投げるときは、「これ、検証は安い？」と一回だけ考えてみてください。けっこう効きます。
